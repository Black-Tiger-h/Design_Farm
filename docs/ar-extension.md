# 3D · AR 공간 배치 데모

2026-10-09 추가 요청에 따라 초기 AR 계획을 데모로 구현했다.

## 현재 체험

- `/space?artwork=sculpture`: 작품 선택을 URL로 유지한다. 갤러리 상세와 주 메뉴에서 연결한다.
- Three.js 가상 공간: 등록 치수(cm)를 미터로 바꾸고, 모델의 경계 상자를 해당 크기에 맞춘다. 원점은 바닥 중심이다. 100%가 등록 크기이며 50~150% 비교, 좌우 이동, 입체 작품 회전, 벽 작품 중심 높이, 벽 색상, 시점 회전·확대·초기화를 제공한다.
- 조소 2점과 도자 2점: 원본 사진을 참고한 수작업 형태와 절차적 색·요철 재질이다. 실제 스캔 모델이 아니다. 회화·섬유 작품 및 사용자가 등록한 모델 없는 작품은 사진 패널로 표시한다. 사진의 배경·프레임도 포함된다.
- WebGL 실패 시 오류를 표시하고 배치 조절을 비활성화한다. 화면을 떠나면 모델, 재질, 텍스처, 렌더러와 이벤트를 정리한다.

## 카메라 AR 구현

- 보안 컨텍스트와 `navigator.xr.isSessionSupported('immersive-ar')`를 확인한다.
- 사용자 버튼 입력 때만 세션과 카메라 권한을 요청한다. `hit-test`, `dom-overlay` 지원을 요구한다. 지원하지 않거나 권한이 거절되면 가상 공간으로 남는다.
- 수평면만 받아 위치 표식을 표시한다. `여기에 놓기` 또는 XR 선택으로 모델을 100% 등록 크기에 배치한다. 다른 수평면을 찾아 재배치할 수 있다.
- 벽 작품은 이번 데모에서 수평면 위에 세운 사진 패널로 표시한다. 수직 벽 인식을 구현한 것으로 설명하지 않는다.
- 종료 시 hit-test를 취소하고 가상 공간과 시점을 복원한다. 컴포넌트가 해제되어도 활성 XR 세션을 끝낸다. 앱은 카메라 영상을 업로드하거나 저장하지 않는다.

## 검증과 제한

- 데스크톱 가상 공간, 작품 교체, 위치·크기·회전, 초기화, 모바일 레이아웃, AR 미지원 안내를 검사했다.
- Node 단위 검사로 치수 변환, 바닥 원점, 크기 비율을 확인했다. 백엔드 통합 검사로 추가 작품의 중복 없는 등록과 기존 계정·입찰·관심 작품 보존을 확인했다.
- 실제 WebXR 기기가 없어 카메라 권한·표면 인식·기기 종료 흐름은 아직 실기기 검증 전이다.
- 현재 서버는 127.0.0.1에만 열린 로컬 앱이다. 다른 휴대폰의 localhost는 그 휴대폰 자체이므로 이 PC 서버에 접속하지 않는다. 실제 모바일 체험은 별도의 승인된 HTTPS 호스팅과 운영용 세션 보안 설정 후 진행한다.
- iOS Quick Look, Android Scene Viewer, USDZ/GLB 파일 내보내기, 환경 차폐·조명 추정, 멀티 작품 배치는 미구현이다.

## 후속 개발

1. 작가가 검증한 GLB/USDZ 자료와 원점·방향·치수 검수. 기존 `model_url/usdz_url`은 여전히 예약 필드다.
2. Android WebXR 실기기에서 권한 거절, 스캔 실패, 재배치, 종료 및 백그라운드 복귀를 검증.
3. 벽 인식과 설치 면별 제약, 실제 색상·크기의 허용 오차 안내.
4. iOS Quick Look 대응, 모델 업로드 검증, 용량·성능 기준 수립.

구현 참고: [Three.js WebXRManager](https://threejs.org/docs/#api/en/renderers/webxr/WebXRManager), [MDN XRSession.requestHitTestSource](https://developer.mozilla.org/en-US/docs/Web/API/XRSession/requestHitTestSource), [Three.js AR hit-test example](https://threejs.org/examples/webxr_ar_hittest.html).
