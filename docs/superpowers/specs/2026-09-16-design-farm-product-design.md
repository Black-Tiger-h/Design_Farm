# Design_Farm 제품 기획서

작성일: 2026-09-16 · 버전: 1.0 · 작성 방식: Superpowers의 요구사항 정리, 대안 비교, 설계 검토 절차 적용

현재 목표: 구매자와 학생 작가의 사용 흐름을 확인하는 HTML 프로토타입.

이 문서는 대화에서 확정된 요구와 현재 `index.html`을 근거로 작성한 제안서다. 시장조사나 실제 고객 검증을 완료했다는 의미는 아니다. 아래에서 **확정**은 사용자가 결정한 사항, **제안**은 이번 기획의 추천, **출시 전 결정**은 실거래 전에 구체화할 사항을 뜻한다. 기능 구현은 별도 작업이다.

## 1. 서비스 개요

**Design_Farm은 예술대학생의 작품을 전시하고, 취향에 맞는 작품을 발견한 구매자가 낮은 시작가부터 경매에 참여하는 온라인 미술관이다.**

학생에게는 평가 이후에도 작품을 소개하고 판매할 기회를, 구매자에게는 신진 작가의 작품을 자신의 공간과 일상에 들일 기회를 제공한다.

추천 운영 방식은 **작은 기획전 단위로 작품과 구매자를 모으는 경매형 플랫폼**이다. 예를 들어 ‘작업실을 나와, 일상에 걸리다’라는 전시에 여러 학생의 작품을 함께 소개한다. 기존 시안의 문구와 미술관 분위기를 이어갈 수 있다.

**추천 이유:** 작품이 생길 때마다 흩어져 등록되는 방식은 초기 구매자의 관심도 분산시킬 수 있다. 같은 기간과 주제로 작품을 소개하면 홍보할 이유와 감상할 동선이 생긴다. 이것이 실제 입찰로 이어지는지는 작은 전시에서 검증한다.

## 2. 확정된 조건과 해석

| 항목 | 적용할 조건 | 이유·주의할 해석 |
|---|---|---|
| 서비스명 | Design_Farm | 사용자가 지정한 이름을 모든 화면에서 일관되게 사용한다. |
| 판매자 | 예술대학생 | 중간·기말 평가를 위해 만든 작품의 다음 쓰임을 만든다. |
| 구매자 | 일반인, 카페·가게 운영자, 신진 작가를 찾는 컬렉터 | 학생의 지인을 초기 핵심 구매자로 삼지 않는다. |
| 구매 가치 | 취향에 맞는 원작을 부담 적은 가격에 소장 | 작품 자체가 구매 이유가 되어야 한다. |
| 예상 가격대 | 1만~10만 원 | 사용자의 마지막 가격 수정에 따른 탐색 기준이다. 모든 시작가나 낙찰가를 이 범위로 강제하는 규칙은 아니다. |
| 경매 원칙 | 학생이 시작가 설정, 한 명만 입찰해도 시작가 이상이면 낙찰 | 시작가가 학생이 실제로 수용하는 판매 최저 금액이어야 한다. |
| 작품 범위 | 실물과 디지털 모두 | 프로토타입에서도 두 유형의 정보 차이를 확인한다. |
| 디지털 판매 횟수 | 사용자가 추후 결정하기로 함 | 단일 소유, 무제한 판매, 한정판 중 어느 하나도 확정된 것처럼 표시하지 않는다. |
| 이번 결과물 수준 | 양쪽 흐름을 체험하는 HTML 프로토타입 | 실제 결제·배송 시스템보다 이해와 사용성 검증에 집중한다. |
| 시각적 분위기 | 미술관 | 작품 사진, 여백, 짧은 작가 노트를 중심으로 설계한다. |

이전의 5만~15만 원 미만 가격대를 현재 기준으로 다시 적용하지 않는다. ‘1만~10만 원’도 지불 의사가 검증된 시장 가격이 아니라 현재 기획 가정이다.

## 3. 해결할 문제와 사용자

작품이 버려진다는 출발점은 창업자의 문제의식이다. 실제 학생이 작품을 얼마나 보관·폐기하는지, 판매하지 않는 이유가 무엇인지는 인터뷰로 확인한다. 판매 의향이 없는 작품까지 등록을 유도하지 않는다.

| 사용자 | 사용하려는 상황 | 제공할 가치 | 설계 이유 |
|---|---|---|---|
| 학생 작가 | 평가가 끝난 작품을 보관하거나 처분하기 전에 다른 방법을 찾는다. | 작품 소개, 직접 정하는 시작가, 판매 과정 안내 | 가격과 전달 방법을 이해해야 등록할 수 있다. |
| 집을 꾸미는 일반인 | 자신의 공간에 어울리는 작품을 찾는다. | 사진·크기·가격·작가 이야기로 선택 | 유명세보다 취향과 공간 적합성을 판단하게 한다. |
| 카페·가게 운영자 | 공간의 분위기를 바꿀 작품을 찾는다. | 재료·크기·상태·배송 조건 확인 | 감상뿐 아니라 실제 설치와 수령 가능성이 중요하다는 가설이다. |
| 신진 작가 컬렉터 | 새로운 작가의 작업을 발견한다. | 작가 소개, 제작 과정, 작품 정보 | 작품과 작가를 함께 이해할 근거를 제공한다. |

**첫 사용성 검증은 일반 구매자와 학생 작가를 우선한다는 제안이다.** 작품 한 점의 발견과 판매라는 기본 흐름을 가장 좁게 확인할 수 있기 때문이다. 카페 운영자와 컬렉터도 대상으로 유지하되, 대량 구매·전문 수집 기능은 수요를 확인한 뒤 검토한다.

구매 화면의 첫 메시지는 ‘취향에 맞는 작품을 소장하세요’로 둔다. 작품의 다음 쓰임과 학생 지원이라는 의미는 작가 노트와 서비스 소개에서 설명한다. ‘버려질 작품 할인 판매’처럼 작품의 가치를 낮추는 표현은 피한다.

## 4. 운영 방식 비교와 선택

| 접근 | 장점 | 감수할 점 | 판단 |
|---|---|---|---|
| 기획전 중심 경매 | 주제와 기간을 함께 홍보하고 작품 감상 흐름을 만들 수 있다. | 작품 모집과 전시 구성에 운영 시간이 든다. | 초기 추천. 소규모 전시로 운영 부담과 거래 성립을 함께 확인한다. |
| 상시 등록 경매 | 학생이 원하는 시점에 등록하기 쉽다. | 초기에는 작품별 방문·입찰이 흩어질 가능성이 있다. | 구매자 유입이 지속되는지 확인한 뒤 확대한다. |
| 정가 판매 중심 | 구매 즉시 거래를 진행할 수 있다. | 학생이 가격을 결정해야 하고 낮은 시작가 참여라는 목적이 약해진다. | 현재 경매 요구와 맞지 않아 기본 방식으로 채택하지 않는다. 실험 비교안으로만 활용한다. |

기획전은 작품의 취향이나 실력을 평가해 서열화하는 제도로 시작하지 않는다. 초기 확인 항목은 사진·정보의 완전성, 주제 적합성, 판매 의향, 전달 가능성으로 둔다. 작가가 작품을 소개할 기회를 불필요하게 줄이지 않기 위해서다.

## 5. 이번 프로토타입의 목표와 기능 우선순위

목표는 ‘실제 거래가 된다’는 주장보다 **사용자가 작품을 이해하고, 규칙을 알고, 등록 또는 입찰을 완료할 수 있는지** 확인하는 것이다.

| 기능 | 현재 시안 | 이번 기획의 우선순위 | 이유 |
|---|---|---|---|
| 작품 목록·이미지·상세 | 있음 | 필수 유지 | 취향에 맞는 작품을 발견하는 출발점이다. |
| 종류 필터·검색·가격 정렬 | 있음 | 필수 유지 | 구매자가 관심 없는 작품을 빠르게 제외할 수 있다. |
| 관심 작품 저장 | 있음 | 필수 유지 | 감상 즉시 입찰하지 않는 사용자도 다시 찾을 수 있다. |
| 작가 노트·크기·재료 | 있음 | 필수 유지 | 구매 판단에 필요한 작품 맥락을 제공한다. |
| 시작가·입찰·마감 결과 | 있음 | 필수 유지 | 핵심 판매 규칙을 체험한다. |
| 판매자 작품 등록 | 있음 | 필수 유지 | 공급자가 등록 과정을 이해하는지 확인한다. |
| 구매·판매 활동 확인 | 있음 | 필수 유지 | 참여 후 상태와 다음 행동을 확인한다. |
| 입찰 전 최종 금액·조건 확인 | 일부 정보만 있음 | 보완 제안 | 금액을 잘못 입력하거나 배송 조건을 놓치는 일을 줄인다. |
| 실물 상태·배송비·액자 포함 여부 | 구체적 입력·표시 없음 | 보완 제안 | 사진만으로 알 수 없는 실제 수령 조건을 드러낸다. |
| 디지털 파일·이용 범위 표시 영역 | 기본 파일 정보와 미정 안내 있음 | 보완 제안 | 파일 수령과 독점 소장을 혼동하지 않게 한다. |
| 낙찰 이후 결제·수령 단계 안내 | 없음 | 화면 설명 보완 제안 | 낙찰이 전체 거래의 끝이 아님을 전달한다. |
| 로그인·학생 인증·실결제·정산 | 없음 | 실거래 준비 단계 | 현재의 흐름 검증 범위를 넘어선다. |
| 실시간 채팅·개인화 추천·SNS 피드·NFT | 없음 | 초기 제외 제안 | 기본 거래 가설을 확인하는 데 필수라는 근거가 아직 없다. |

현재 시안의 입찰·등록 정보는 브라우저 메모리에 있고 새로고침하면 초기화된다. 가상의 작품·작가·입찰을 사용한다. 실제 여러 사람이 참여하는 경매가 구현된 상태로 설명하지 않는다.

## 6. 화면 구성과 구매·판매 흐름

메뉴는 **작품 둘러보기 / 내 활동 / 작품 등록**으로 유지한다. 내 활동 안에서는 ‘구매’와 ‘판매’를 명확히 구분한다. 한 사람이 두 역할을 겸할 수 있어 계정을 나누지 않아도 된다.

| 화면 | 핵심 내용·행동 | 구성 이유 |
|---|---|---|
| 전시 홈 | 전시 소개, 대표 작품, 전체 작품 보기 | 서비스가 무엇인지 작품과 함께 이해한다. |
| 작품 목록 | 이미지, 제목, 작가, 유형, 시작가 또는 현재가, 마감 | 비교에 필요한 최소 정보를 함께 보여준다. |
| 작품 상세 | 큰 이미지, 작품 정보, 작가 노트, 전달 조건, 입찰 | 감상에서 구매 판단으로 자연스럽게 이어진다. |
| 입찰 확인 | 입력 금액, 배송비, 현재 기준 부담액, 낙찰 규칙 | 금액과 약속을 확인한 뒤 참여한다. |
| 작품 등록 | 사진, 정보, 전달 방법, 시작가, 기간, 등록 전 요약 | 입력 직후 경매가 시작된다는 점을 이해하게 한다. |
| 내 활동 | 관심 작품, 참여 경매, 등록 작품, 결과와 다음 행동 | 사용자가 참여 내용을 되찾고 처리할 수 있다. |

### 구매자 흐름

1. 전시 홈에서 작품 목록으로 이동한다.
2. 종류·가격·검색으로 작품을 탐색하고 관심 작품을 저장한다.
3. 상세에서 이미지, 크기, 상태, 작가 노트, 전달 조건을 읽는다.
4. 입찰 금액을 입력하고 조건을 확인한다.
5. 제출 결과로 ‘현재 최고 입찰’ 또는 실패 이유를 확인한다.
6. 내 활동에서 진행 중·다른 입찰자 우위·낙찰·미낙찰 상태를 확인한다.
7. 프로토타입에서는 마감 체험까지 진행하고, 이후 결제·전달 단계는 안내로 이해한다.

**이유:** 작품을 좋아하는 것과 입찰 약속을 하는 것 사이에는 가격·조건 확인이 필요하다. 제출 이후에는 자신의 상태를 즉시 알 수 있어야 한다.

### 판매자 흐름

1. 작품 등록을 선택한다. 실서비스에서는 학생 자격과 판매 가능 상태를 확인한다.
2. 실물 또는 디지털 유형에 맞는 정보를 입력한다.
3. 전달 방법과 비용을 정하고, 수용 가능한 시작가와 기간을 선택한다.
4. ‘한 명만 이 금액에 입찰해도 낙찰된다’는 안내와 등록 내용을 확인한다.
5. 등록 후 내 활동에서 작품과 경매 상태를 확인한다.
6. 낙찰이면 결제 대기·전달 준비를, 유찰이면 정보 수정 후 재등록을 선택한다.

**이유:** 학생이 가장 낮은 판매 결과까지 예상하고 등록하게 한다. 유찰 작품의 가격을 시스템이 임의로 내리지 않는다.

## 7. 경매 규칙

| 항목 | 규칙 | 상태 | 이유 |
|---|---|---|---|
| 시작가 | 판매자가 직접 설정한다. | 확정 | 수용 가능한 판매 금액을 학생이 결정한다. |
| 단독 입찰 | 마감 시 유효 입찰자가 한 명이어도 시작가 이상이면 해당 금액에 낙찰한다. | 확정 | 사용자가 선택한 경매 원칙이다. |
| 숨은 최저 낙찰가 | 시작가보다 높은 별도 최저 낙찰가를 두지 않는다. | 확정 원칙의 적용 | 단독 입찰 낙찰 조건과 모순되지 않게 한다. |
| 첫 입찰 | 시작가부터 가능하다. | 제안·현행 시안 | 첫 참여의 조건을 단순하게 한다. |
| 추가 입찰 | 현재 최고가보다 최소 1,000원 높고 1,000원 단위여야 한다. | 제안·현행 시안 | 금액 계산이 쉬우며 현재 체험과 연결된다. |
| 예상 가격대 | 1만~10만 원을 초기 작품 구성의 기준으로 삼는다. 낙찰 상한으로 보장하지 않는다. | 제안 | 낮은 가격의 접근성과 경매 결과를 구분한다. |
| 기간 | 3일 기본, 1일·7일 선택을 유지한다. | 제안·현행 시안 | 기간에 대한 사용자의 이해와 선호를 비교할 수 있다. |
| 마감 | 프로토타입은 정해진 시각에 마감한다. 자동 연장·자동 입찰은 넣지 않는다. | 제안 | 우선 기본 규칙의 이해를 검증한다. |
| 동시 입찰 | 실서비스에서는 서버가 먼저 접수한 유효 입찰만 반영하고, 뒤 요청에는 변경된 최소가를 알려준다. | 실거래 요구 | 같은 금액의 최고 입찰자가 두 명 생기지 않게 한다. |
| 자기 작품 입찰 | 금지한다. 현재 시안은 화면에서 차단하며 실서비스는 서버에서도 확인한다. | 제안 | 가격을 인위적으로 올리는 행위를 줄인다. |
| 입찰 없음 | 유찰 처리하고 학생이 재등록 여부를 선택한다. | 제안·일부 현행 | 자동 인하나 판매 강요를 피한다. |
| 정보 변경 | 첫 입찰 이후 가격·상태·구성·전달 조건을 임의로 변경하지 않는다. | 실거래 제안 | 구매자가 읽고 입찰한 조건을 유지한다. |
| 취소·오입찰 | 실거래 전 처리 기준을 확정한다. 그전에는 ‘어떠한 경우에도 취소 불가’ 같은 약속을 만들지 않는다. | 출시 전 결정 | 사용자가 이해하고 운영자가 실행할 수 있는 절차가 필요하다. |

예시: 시작가 10,000원, 입찰 한 번 10,000원 → 10,000원 낙찰. 시작가 10,000원, 유효 입찰 12,000원·18,000원 → 18,000원 낙찰. 입찰이 없으면 유찰이다.

‘입찰 5회’와 ‘입찰자 5명’은 다르다. 현재 시안이 가진 입찰 횟수를 인원수처럼 표시하지 않는다.

## 8. 작품 정보와 신뢰

| 구분 | 필요한 정보 | 이유 |
|---|---|---|
| 공통 | 제목, 작가 표시명, 제작 시기, 분야, 작가 노트, 대표 이미지 | 작품과 제작자를 구별하고 이해한다. |
| 실물 | 재료, 가로·세로·높이, 상태·흠집, 상세 사진, 액자·부속품 포함 여부 | 구매자가 실제 받는 구성을 알게 한다. |
| 실물 전달 | 배송·직접 수령 가능 여부, 배송비, 발송 예정 기간 | 입찰 전 비용과 수령 가능성을 판단한다. |
| 디지털 | 형식, 해상도·길이 등 매체 정보, 제공 파일 목록, 전달 방식 | 미리보기와 실제 파일의 차이를 설명한다. |
| 디지털 이용 | 판매 횟수, 독점 여부, 허용 용도, 재배포·재판매 조건 | 구매자가 받는 이용 범위에 대한 기대 차이를 줄인다. |
| 학생 확인 | 학생 자격 확인 상태와 작가 소개 | 학생 플랫폼이라는 약속의 근거를 제공한다. |

학생 자격 확인은 작품 진위나 저작권을 보증한다는 뜻으로 사용하지 않는다. 실제로 확인한 사실만 표시한다. 인증을 수행하지 않는 프로토타입에는 가짜 인증 배지를 붙이지 않는다.

디지털 판매 횟수와 이용 조건은 사용자의 후속 결정으로 남긴다. 현재 프로토타입은 ‘정책 미정인 체험’임을 알리고, 디지털 작품을 일괄적으로 ‘유일한 원작’이라고 홍보하지 않는다. 첫 실거래 출시 범위는 실물과 디지털 모두 유지하되 디지털 조건 확정을 출시 조건으로 둔다.

## 9. 낙찰 이후의 거래

실거래의 상태는 다음처럼 구분한다.

**경매 진행 → 마감·낙찰 또는 유찰 → 낙찰자 결제 대기 → 결제 완료 → 작품 전달 → 수령 확인·문제 접수 → 거래 완료·정산**

**이유:** 낙찰만으로 결제·배송·수령이 끝난 것은 아니다. 각 상태에서 누가 다음 행동을 해야 하는지 구매자와 판매자 모두에게 보여준다. 현재 프로토타입의 ‘낙찰 완료’는 경매 결과만 뜻한다.

실거래 전에는 결제 기한, 미결제 처리, 발송 기한, 미배송·파손 처리, 취소·환불, 정산 시점을 정한다. 낙찰자가 결제하지 않았다고 차순위 입찰자에게 자동 결제하거나 구매를 강제하지 않는 방안을 제안한다. 필요하면 별도 구매 의사를 확인한다.

디지털은 확정된 이용 조건에 동의하고 결제가 완료된 후 원본 파일을 제공하는 흐름을 제안한다. 공개 미리보기와 전달용 파일을 구분한다.

## 10. 미술관 분위기의 디자인 원칙

| 원칙 | 화면 적용 | 이유 |
|---|---|---|
| 작품이 먼저 보인다 | 큰 이미지와 충분한 여백, 중립적인 바탕색 | 서비스 장식이 작품의 색과 형태를 가리지 않는다. |
| 정보는 읽기 쉽다 | 전시 제목에 개성을 주고 본문·가격은 가독성을 우선한다. | 감상 경험과 거래 정보 이해를 함께 확보한다. |
| 감상에서 소장으로 이어진다 | 작가 노트와 상세 정보를 읽은 자리에서 입찰할 수 있다. | 구매 판단의 근거와 행동을 연결한다. |
| 경매 조건은 분명하다 | 가격·마감·배송비·버튼은 배경과 충분히 구별한다. | 미술관 분위기가 필수 정보를 찾기 어렵게 만들지 않는다. |
| 작품을 과장하지 않는다 | 가상의 인기·조회수·인증·희소성 표시를 넣지 않는다. | 사용자의 판단 근거를 실제 정보에 둔다. |
| 모바일에서도 감상할 수 있다 | 한 열 작품 목록, 읽기 쉬운 본문, 누르기 쉬운 버튼 | 작은 화면에서도 발견과 입찰 과정을 수행한다. |
| 누구나 기본 동작을 수행한다 | 키보드 이동, 이미지 설명, 입력 오류 안내, 색 이외의 상태 표시 | 작품 확인과 참여에 불필요한 장벽을 만들지 않는다. |

추천 대표 문구: **“작업실을 나와, 일상에 걸리다.”** 실물 작품 전시에 적합하다. 디지털까지 포괄하는 서비스 설명은 **“새로운 작가의 작품을 발견하고 소장하는 곳.”**으로 제안한다.

## 11. 수익 모델 제안

초기 수익 모델은 **거래가 완료되었을 때 발생하는 판매 수수료** 한 가지부터 검증한다. 수수료율은 아직 확정하지 않는다. 학생이 등록 전에 예상 공제와 수령액을 볼 수 있게 한다.

**이유:** 거래가 없는 상태에서 등록비를 받으면 작품 공급을 어렵게 할 수 있다. 거래 완료 수수료는 판매 성공과 플랫폼 수익을 연결한다. 다만 저가 작품은 건당 수익이 작아질 수 있으므로 실제 비용을 함께 측정해야 한다.

건당 기여액 = 플랫폼이 실제 수취한 수수료 − 결제 처리비 − 플랫폼 부담의 환불·배송 지원비 − 건당 운영·고객 대응 비용.

이 값이 낮거나 음수라면 먼저 수작업과 배송 지원 구조를 점검한다. 이후 수수료율·최소 수수료를 구매자·판매자 이탈과 함께 비교한다. 광고, 작가 구독, 유료 상위 노출은 초기 필수 기능으로 제안하지 않는다.

## 12. 초기 운영과 출시 순서

| 단계 | 실행할 일 | 다음 단계로 가는 기준 | 이유 |

인원과 작품 수는 운영 규모를 가늠하기 위한 제안이며 확정된 모집 수나 성공 보장이 아니다. 일정은 참여자 모집과 팀의 구현 가능 범위를 확인한 뒤 정한다.

모집·홍보 후보는 대학 미술 관련 커뮤니티, 공간 꾸미기 커뮤니티, 카페 운영자 모임이다. 광고비를 쓰기 전에 전시를 보고 작품 상세로 이동하는지부터 확인한다. 이 문서는 실제 모집이나 게시를 실행한 결과가 아니다.

## 13. 검증 계획과 지표

### 프로토타입 검증

학생 작가 5명과 지인 관계가 없는 구매자 후보 5명을 대상으로 시작하는 방안을 제안한다. 작은 표본의 사용성 점검이며 전체 시장의 비율을 추정하는 조사가 아니다.

| 검증할 가설 | 과제·질문 | 관찰할 결과 | 판단 이유 |
|---|---|---|---|
| 작품 정보가 구매 판단에 충분하다 | 예산 7만 원으로 자신의 공간에 둘 작품 한 점을 고르고 이유를 설명한다. | 선택 이유, 부족한 사진·정보, 배송비 확인 여부 | 단순히 예쁘다는 반응을 넘어 구매 판단의 근거를 본다. |
| 경매를 이해한다 | 1만 원 시작가에 자신만 1만 원을 입찰한 상황을 설명하게 한다. | 낙찰 여부와 금액을 정확히 말하는지 | 핵심 약속을 오해하면 실제 거래에 문제가 생긴다. |
| 학생이 시작가 결과를 수용한다 | 실제 판매할 의향이 있는 작품과 단독 낙찰을 수용할 시작가를 정한다. | 등록 가능한 작품, 수용 가격, 망설임 | 막연한 서비스 호감과 실제 판매 의향을 구분한다. |
| 양쪽 사용 흐름을 수행한다 | 도움 없이 입찰 및 작품 등록 과제를 수행한다. | 성공·실패 단계, 오류, 필요한 도움 | 디자인과 입력 절차의 문제를 찾는다. |
| 디지털 구매 대상을 이해한다 | 상세를 보고 무엇을 받으며 무엇이 아직 미정인지 설명한다. | 파일 수령과 독점성·이용 조건을 구분하는지 | 미정인 권리를 확정된 것으로 오해하는지 확인한다. |

초기 개선 기준은 역할별 5명 중 4명 이상이 핵심 과제를 도움 없이 수행하는 것으로 제안한다. 단독 낙찰·배송비·디지털 이용 조건의 오해가 한 건이라도 발견되면 해당 안내를 검토한다. 이 수치는 검증된 업계 기준이 아니라 팀의 첫 반복 작업을 위한 임시 기준이다.

경매 자체가 구매를 망설이게 하는지 확인하려면 같은 작품의 경매안과 정가안을 비교할 수 있다. 제시 순서를 바꾸고 선택 이유를 기록한다. 클릭 선호만으로 실구매가 검증되었다고 판단하지 않는다.

### 실제 거래 지표

핵심 지표는 **지인 외 구매자가 참여해 결제·전달까지 완료한 거래 수**로 제안한다. 플랫폼이 학생과 새로운 구매자를 연결한다는 목적에 직접 대응한다. 지인 여부는 참여자 응답으로 확인하고 응답이 없으면 ‘미확인’으로 남긴다.

| 지표 | 계산·집계 기준 | 해석 |
|---|---|---|
| 입찰 발생 작품 비율 | 관찰 기간에 정상 마감한 작품 중 유효 입찰이 한 번 이상 있는 작품 수 / 정상 마감 작품 수 | 작품 공급에 구매 수요가 붙는지 본다. |
| 작품당 고유 입찰자 수 | 한 작품에 유효 입찰한 서로 다른 구매자 수 | 반복 입찰 횟수를 인원으로 오인하지 않는다. |
| 낙찰 후 결제율 | 결제 기한이 지난 낙찰 건 중 기한 내 결제된 건 / 결제 기한이 지난 낙찰 건 | 입찰 의사가 결제로 이어지는지 본다. |
| 거래 완료율 | 수령 확인 예정 시점이 지난 결제 건 중 거래 완료 건 / 해당 결제 건 | 최근 결제 건을 성급히 실패로 집계하지 않는다. |
| 가격 분포 | 정상 마감한 낙찰 작품의 낙찰가 중앙값·분포, 별도의 배송비 | 1만~10만 원 가정과 실제 부담을 비교한다. |
| 재참여 | 후속 전시에 재등록한 학생 수, 재방문·재구매한 구매자 수와 관찰 기간 | 일회성 관심과 반복 사용을 구분한다. |
| 건당 기여액·운영 시간 | 완료 거래별 실제 수익·비용·대응 시간 | 매출이 늘어도 운영이 지속 가능한지 확인한다. |

운영 취소 작품은 정상 마감 지표에서 분리하되 취소 수와 사유를 함께 보고한다. 가상의 입찰과 실제 이용 데이터를 섞지 않는다. 아직 측정 결과는 없다.

## 14. 주요 불확실성과 대응

| 불확실성 | 대응 | 대응 이유 |
|---|---|---|
| 등록은 많고 입찰은 적을 수 있다 | 작품 수를 무조건 늘리기 전에 구매자 유입·작품 적합성·조건 정보의 문제를 나눠 확인한다. | 원인이 다른 문제에 같은 처방을 하지 않는다. |
| 학생이 낮은 낙찰가를 받아들이지 않을 수 있다 | 등록 전 단독 낙찰 예시와 예상 수령액을 보여주고 수용 시작가를 받는다. | 낙찰 후 약속을 바꾸는 상황을 줄인다. |
| 배송 부담이 작품 가격 대비 클 수 있다 | 입찰 전에 배송비와 수령 선택지를 표시한다. | 작품 가격만 보고 참여한 뒤 포기하는 일을 줄인다. |
| 디지털 독점성에 대한 기대가 다를 수 있다 | 이용 조건을 확정하고 작품별로 읽을 수 있게 한다. | 실물 원작과 동일한 기대를 자동 적용하지 않는다. |
| 낙찰자가 결제하지 않을 수 있다 | 실거래 전에 결제 기한·알림·미결제 처리 기준을 마련한다. | 낙찰과 실제 판매 성과를 구분한다. |
| 작은 거래에 운영 시간이 많이 들 수 있다 | 거래마다 대응 시간을 기록하고 반복 문의를 정보·절차 개선에 반영한다. | 저가 거래에서도 감당 가능한 운영을 찾는다. |

현재 최선의 계획을 추천한 것이며, 이러한 불확실성이 실제로 해소되어 최적임이 입증된 것은 아니다.

## 15. 프로토타입 확인 항목과 다음 결정

다음 항목은 향후 보완 구현 후 수행할 확인 기준이다. 이 문서 작성 시점에 해당 구현·검증을 모두 마쳤다는 뜻은 아니다.

1. 구매자가 실물과 디지털 작품을 구분해 찾고 상세를 열 수 있다.
2. 첫 입찰은 시작가에 가능하고, 그보다 낮은 금액은 이유와 함께 거절된다.
3. 추가 입찰은 현재 최고가와 입찰 단위 규칙을 따른다.
4. 시작가 10,000원에 입찰이 하나이면 10,000원에 낙찰된다.
5. 입찰이 없으면 유찰되고, 마감 이후 입찰은 접수되지 않는다.
6. 등록자는 자신의 작품에 입찰할 수 없다.
7. 작품 정보와 시작가를 확인하고 등록한 뒤 내 활동에서 찾을 수 있다.
8. 실물 상세에서 상태·구성·배송비를, 디지털 상세에서 파일 정보와 정책 상태를 확인할 수 있다.
9. 낙찰 상태와 결제·수령 완료 상태를 혼동하지 않는다.
10. 키보드와 모바일 화면에서 탐색·등록·입찰의 기본 동작을 수행할 수 있다.

후속 결정의 우선순위는 다음과 같다.

| 순서 | 결정할 내용 | 결정 자료 |
|---|---|---|
| 1 | 학생이 수용하는 시작가와 구매자의 선택 이유 | 양쪽 인터뷰·사용성 관찰 |
| 2 | 디지털 판매 횟수·독점 여부·이용 범위 | 학생 창작자의 판매 의도와 구매자의 사용 목적 |
| 3 | 수수료·결제·전달·문제 처리 조건 | 예상 운영 절차와 비용, 적용 가능한 결제·거래 조건의 검토 |
| 4 | 작은 기획전의 참여 규모와 기간 | 모집 가능 작품 수와 구매자 유입 경로 |

제품의 기본 흐름은 **작품 발견 → 정보 확인 → 입찰 → 낙찰 → 전달**이다. 각 단계가 이해되고 실제로 이어지는 근거를 확보한 뒤 기능과 운영 규모를 넓힌다.
