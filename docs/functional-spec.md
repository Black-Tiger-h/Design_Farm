# Design_Farm 기능명세서

버전: 1.0 초안 · 작성일: 2026-09-18 · 대상: Next.js + FastAPI + Supabase 기반 웹앱

## 1. 목적과 적용 범위

예술대학생의 작품을 전시하고, 구매자가 작품의 크기와 작가의 공간 제안을 살펴 소장할 작품을 선택하도록 돕는다. 작가는 거래 실적과 포트폴리오를 통해 스카우트·외주 기회를 얻는다.

현재 구현은 `index.html` 프로토타입이다. **이 문서는 앞으로 개발할 기능의 명세이며 구현 완료 보고서가 아니다.** 초기 기획서의 화면 구성보다 최근 사용자 요구와 승인된 README의 기술 구성을 우선한다.

| 구분 | 내용 |
| --- | --- |
| 사용자 확정 | Design_Farm 이름, 미술관 분위기, 예술대학생 작품, 실물·디지털 전시, 작가의 크기·공간 안내, 경매, 커리어 순위, 스카우트·외주 요청 |
| 사용자 확정 | 학생이 시작가 설정, 단독 입찰도 시작가 이상이면 낙찰, 예상 가격 1만~10만 원은 강제 범위가 아님 |
| 기술 승인 | Next.js + TypeScript, FastAPI + Python, Supabase PostgreSQL·Auth·Storage |
| 개발 기준안 | 아래의 입력 제한, 화면 경로, 이메일 로그인, 수정 제한, 요청 상태 및 검증 기준. 구현을 구체화하기 위한 제안이며 별도 승인된 운영 정책은 아님 |
| 별도 결정 | 실결제·정산·배송·환불 정책, 학생 인증 방법, 디지털 판매 횟수·이용 권한, 운영 배포 서비스 |

### 개발 단계

- **M1 — 전시 기반:** 계정·작가 프로필·작품·공간 안내·관심 작품을 서버에 저장한다.
- **M2 — 경매와 커리어:** 여러 테스트 계정의 입찰·마감, 작가 목록·순위, 협업 요청과 수신함을 구현한다. 실제 금전 거래는 발생하지 않는 테스트 운영 단계다.
- **L — 실거래 출시:** 결제·전달·정산·학생 인증·분쟁 정책을 확정하고 별도 상세 명세를 작성한 뒤 활성화한다. M2 완료를 실거래 출시로 간주하지 않는다.

개인화 AI 추천, 방 사진 합성·AR 배치, 실시간 채팅, SNS 피드, NFT, 앱스토어용 네이티브 앱은 이번 범위에 포함하지 않는다. 공간 추천은 학생 작가가 직접 작성한다.

## 2. 사용자와 권한

한 계정이 구매자와 작가를 겸한다. 작가는 이름이 아닌 고유 ID로 식별하며, 로그인했다고 학생 인증이 완료된 것으로 표시하지 않는다.

| 사용자 | 허용 기능 | 제한 |
| --- | --- | --- |
| 비회원 | 공개 작품·작가·공간 안내·순위 조회, 검색 | 저장·입찰·등록·협업 요청 시 로그인 필요 |
| 로그인 회원 | 관심 작품, 타인 작품 입찰, 타인 작가에게 협업 요청, 본인 활동 조회 | 타인 비공개 정보·요청·작품 수정 불가 |
| 작가 프로필 보유 회원 | 본인 작품 등록·관리, 본인 작가 수신함 | 본인 작품 입찰·본인에게 협업 요청 불가 |
| 운영자 | 신고 확인, 사유를 남긴 노출 중단·경매 취소, 운영 기록 조회 | 임의 입찰·낙찰자 변경 불가. 권한은 서버에서만 부여 |

M1·M2의 작가 등록은 테스트 계정으로 허용하고 학생 여부는 미인증으로 표시한다. 실거래 작품 공개에는 L 단계에서 정할 학생 확인 기준을 적용한다.

## 3. 화면과 주요 동선

경로는 구현 기준안이다. PC·모바일 모두 같은 계정과 데이터를 사용한다.

| 화면 | 경로 | 주요 기능 |
| --- | --- | --- |
| 미술관 홈 | `/` | 서비스 소개, 대표 작품, 공간별 탐색·작가와 커리어 진입 |
| 작품 목록 | `/artworks` | 종류·공간 필터, 검색·정렬, 관심 작품 |
| 작품 상세 | `/artworks/{id}` | 이미지·크기·작가 노트·공간 제안·경매 상태·입찰 |
| 회원 | `/login`, `/signup`, `/reset-password` | 로그인·가입·비밀번호 재설정 |
| 작품 작성·수정 | `/studio/artworks/new`, `/studio/artworks/{id}/edit` | 초안 저장, 미리보기, 전시 공개·경매 시작 |
| 작가 목록·순위 | `/artists` | 작가 탐색, 실적 기준과 순위 |
| 작가 상세 | `/artists/{id}` | 소개·포트폴리오·실적, 스카우트·외주 요청 |
| 내 활동 | `/me` | 구매 경매·판매 경매·관심 작품·등록 작품 |
| 협업 요청함 | `/me/inquiries` | 보낸 요청·받은 요청·상세·상태 변경 |
| 프로필 설정 | `/me/profile` | 본인 표시명·작가 소개 수정 |
| 운영 | `/admin` | 운영 권한 사용자만 접근, 신고·노출 중단·취소 기록 |

구매자: 전시 → 공간별 탐색 → 작품 상세 → 로그인 → 입찰 확인 → 입찰 결과 → 내 활동.

학생 작가: 가입 → 작가 프로필 → 작품 초안 → 크기·공간 안내 → 전시 공개 → 테스트 경매 → 결과 확인.

협업 제안자: 작가 목록 → 포트폴리오 → 요청 작성 → 보낸 요청. 작가: 받은 요청 → 상세 → 수락 또는 거절.

## 4. 기능 목록과 완료 기준

기능 ID는 추후 개발 작업과 테스트에서 공통으로 참조한다. 모든 변경 요청은 화면과 별개로 서버에서 권한·입력값을 검사한다.

### 4.1 계정과 작가 프로필 — M1

| ID | 기능 | 처리 및 예외 | 완료 기준 |
| --- | --- | --- | --- |
| AUTH-01 | 이메일 회원가입·확인 | 이메일·비밀번호를 Supabase Auth로 처리. 중복 가입·인증 실패 안내. 비밀번호를 서비스 DB나 로그에 저장하지 않음 | 이메일 확인 후 로그인 가능. 미확인 계정의 입찰·작품 공개·요청 전송 거절 |
| AUTH-02 | 로그인·로그아웃·재설정 | 인증 만료 시 재로그인 안내. 재설정 요청은 이메일 존재 여부가 노출되지 않는 동일 안내 사용 | 새로고침 후 세션 유지, 로그아웃 후 보호 기능 접근 차단 |
| AUTH-03 | 로그인 후 돌아오기 | 비회원의 보호 동작 시 로그인으로 이동하고 앱 내부 원래 페이지로 복귀 | 로그인만으로 입찰·요청이 자동 실행되지 않음 |
| ARTIST-01 | 작가 프로필 작성 | 표시명·학교·전공·소개 저장. 학교·전공은 자기기재이며 인증 표시와 분리 | 동명이인도 별도 프로필·작품·실적으로 조회 |
| ARTIST-02 | 프로필 수정 | 본인만 수정. 사용자 입력으로 인증·운영 권한 변경 불가 | 타인 ID를 넣은 수정 요청 거절 |

### 4.2 작품 감상과 공간 안내 — M1

| ID | 기능 | 처리 및 예외 | 완료 기준 |
| --- | --- | --- | --- |
| GALLERY-01 | 전시 홈 | 공개 작품과 서비스 소개 노출. 비공개·중단 작품 제외 | 작품이 없어도 안내와 탐색 메뉴가 표시됨 |
| GALLERY-02 | 목록·검색·필터 | 작품명·작가명 검색, 종류·추천 공간 필터를 AND 조건으로 결합. 초기화 제공 | 새로고침·뒤로 가기에도 URL의 검색 조건 유지, 결과 없음 안내 |
| GALLERY-03 | 정렬·페이지 이동 | 기본 최신 공개순. 낮은 가격순은 현재 최고가 또는 시작가, 마감순은 진행 경매만 대상. 가격 없는 전시 작품은 가격순 뒤에 배치 | 동률은 작품 ID로 정렬해 순서 고정. 페이지당 24점 기준안 |
| GALLERY-04 | 작품 상세 | 이미지, 작가, 재료, 크기/파일 정보, 노트, 추천 공간·배치 안내를 가격과 함께 표시 | 실물 cm와 디지털 px 구분. 비공개 작품은 소유자·운영자만 조회 |
| SPACE-01 | 작가의 공간 제안 | 추천 공간 1개와 배치 설명 필수. 작품 크기를 함께 표시하고 작성 주체를 작가로 명시 | 서재 필터로 찾은 작품 상세에서 크기와 서재 배치 설명 확인 가능 |
| SAVE-01 | 관심 작품 저장·해제 | 계정·작품 쌍 중복 저장 방지. 비공개 전환 작품은 관심 목록에서 접근 불가 안내 | 다른 기기·새로고침에도 저장 유지. 반복 저장 시 건수 증가 없음 |

### 4.3 작품 등록과 관리 — M1, 경매 시작은 M2

| ID | 기능 | 처리 및 예외 | 완료 기준 |
| --- | --- | --- | --- |
| WORK-01 | 초안 저장 | 작가 프로필 필요. 작성 중 저장 허용, 공개 시 전체 필수값 검증. 작가 ID는 로그인 계정으로 결정 | 재접속 후 본인 초안 복원, 타인이 초안 조회 불가 |
| WORK-02 | 이미지 업로드 | JPG·PNG·WEBP, 이미지 내용·크기 검사. 원본 디지털 판매 파일과 공개 미리보기 구분 | 실패 시 다른 입력 유지. 이미지 없는 작품 공개 거절 |
| WORK-03 | 미리보기·전시 공개 | 일반 감상용 전시와 경매를 분리. 공개 전 구매자 시점의 정보 확인 | 공개 작품이 목록·작가 포트폴리오에 나타남 |
| WORK-04 | 수정·비공개·삭제 | 진행 경매와 낙찰 작품의 거래 조건 수정 금지. 경매 시작 전 초안·전시 작품 수정 가능. 경매 기록 없는 작품만 삭제 가능 | 경매가 시작된 뒤 이미지·제목·크기·시작가·마감 변경 시 거절. 오류 정정은 운영 취소 후 새 등록 |
| WORK-05 | 경매 시작 (M2) | 소유자만 시작. 공개 작품·필수값·기간·시작가 확인 및 단독 입찰 낙찰 안내 확인 | 작품당 동시에 하나의 경매만 생성. 시작 이후 거래 조건 스냅샷 보존 |

### 4.4 경매 — M2

| ID | 기능 | 처리 및 예외 | 완료 기준 |
| --- | --- | --- | --- |
| BID-01 | 경매 정보·확인 | 시작가·현재가·최소 입찰액·서버 마감 시각·테스트 거래 표시. 입력 후 최종 금액 재확인 | 취소 시 입찰 없음. 가격 변동 시 금액을 자동 인상하지 않고 재확인 요구 |
| BID-02 | 입찰 접수 | 인증 회원, 타인 작품, 진행 중 경매에 한함. DB 트랜잭션에서 최신 가격·시간을 재검증 | 동시 동일 금액 요청은 하나만 성공. 낮은 금액·잘못된 단위·마감 후 입찰 거절 |
| BID-03 | 입찰 재시도 | 요청별 중복 방지 키 사용. 같은 회원·같은 키·같은 내용의 재시도는 최초 결과 반환, 내용이 다르면 충돌 | 응답 유실 후 재시도해도 입찰 기록 한 건. 브라우저 재접속 후 내 활동으로 결과 확인 가능 |
| BID-04 | 마감·유찰 | 서버가 기한 지난 경매를 주기적으로 마감. 입찰 없음은 유찰, 있음은 최고가 낙찰 | 한 명의 10,000원 입찰은 10,000원 낙찰. 서버 재시작·마감 재실행에도 결과 한 건 |
| BID-05 | 결과 조회 | 낙찰자·판매자에게 본인 결과 제공. 공개 화면은 금액·상태만 제공 | 낙찰과 거래 완료를 별도 표시. 타인의 연락처·회원 ID 노출 없음 |

### 4.5 작가 커리어와 협업 — M2

| ID | 기능 | 처리 및 예외 | 완료 기준 |
| --- | --- | --- | --- |
| CAREER-01 | 작가 목록·포트폴리오 | 공개 프로필과 공개 작품 표시. 순위 밖 작가도 검색·열람 가능 | 거래 실적이 없어도 작가 페이지와 작품을 볼 수 있음 |
| CAREER-02 | 거래 실적·순위 | 거래 완료 건수 내림차순. 동률 공동 순위(1, 2, 2, 4), 같은 순위 내부는 작가 ID 순. 전체 기간 집계 기준안 | 진행·유찰·취소·환불 제외. 작품 비공개 전환만으로 완료 거래 실적이 사라지지 않음 |
| CAREER-03 | 테스트 실적 구분 | M2는 테스트 데이터의 완료 상태를 별도 테스트 절차로 생성. 사용자에게 테스트 순위임을 표시 | 낙찰만으로 완료 실적 증가 없음. 실제 운영 데이터에 테스트 거래를 합산하지 않음 |
| INQUIRY-01 | 스카우트·외주 요청 작성 | 로그인 후 유형·보내는 이름/단체·연락 이메일·내용 입력. 수신 작가는 화면의 작가 ID로 고정. 본인에게 요청 불가 | 재전송에도 같은 요청 한 건. 실패 시 입력 유지, 성공 시 보낸 요청에 표시 |
| INQUIRY-02 | 받은·보낸 요청 조회 | 발신자는 본인 요청, 수신 작가는 자신에게 온 요청만 조회. 일반 회원에게 연락처 비공개 | 다른 계정으로 요청 ID를 직접 조회해도 내용에 접근 불가 |
| INQUIRY-03 | 읽음·수락·거절·취소 | 수신자 상세 열람 시 읽음. 수신자만 수락/거절, 발신자는 대기·읽음 상태에서 취소. 터미널 상태는 변경 불가 | 동시 수락·취소 중 먼저 확정된 하나만 적용. 수락은 연락 의향이며 외주 계약·결제가 아님 |

M2 요청 전달은 **앱 내부 수신함 저장**을 의미한다. 실시간 채팅·이메일 발송·푸시 알림은 포함하지 않는다. 연락처는 당사자가 상세 화면에서 확인한다.

## 5. 주요 입력값 기준안

기존 시안의 제한을 가능한 한 유지한다. 공백만 있는 필수 문자열은 거절하고 앞뒤 공백을 제거한다. 사용자 텍스트는 HTML로 실행하지 않는다. 아래 수치는 개발 기준안이며 검증 후 조정할 수 있다.

| 입력 | 필수 조건·검증 |
| --- | --- |
| 작가 프로필 | 표시명 1~30자, 학교·전공 각각 1~100자, 소개 1~500자 |
| 작품명·재료 | 공개 시 작품명 1~60자, 재료/제작 방식 1~100자 |
| 작품 종류 | 회화 / 조소·공예 / 디지털 중 1개. 회화·조소는 실물, 디지털은 파일 작품으로 분류 |
| 실물 크기 | 가로·세로 필수, 깊이 선택. cm 단위, 각 값 0 초과 10,000 이하, 소수 둘째 자리까지 |
| 디지털 정보 | 파일 형식 1~30자, 가로·세로 px 각각 양의 정수 최대 100,000. 원본 파일 제출은 L 단계 |
| 이미지 | 공개 시 1~5장, 장당 최대 5MB, JPG·PNG·WEBP. 실제 디코딩 가능하고 가로·세로 각각 10,000px 이하. 대표 이미지 1장 지정 |
| 작가 노트 | 공개 시 1~500자 |
| 추천 공간 | 거실 / 침실 / 서재 / 카페·매장 / 디지털 공간 / 기타 중 1개 |
| 배치 제안 | 공개 시 1~180자. 크기와 배치 위치를 안내하는 도움말 제공 |
| 시작가·입찰가 | 1,000~100,000,000원, 1,000원 단위 정수. 상한은 현재 시안의 기술 제한을 유지한 기준안이며 예상 가격대와 별개 |

| 신고 | 사유 1~500자. 동일 회원의 같은 작품에 대한 미처리 신고는 중복 생성하지 않음 |

파일 저장 성공 후 작품 저장이 실패하면 이미 업로드한 파일을 재사용하거나 정리할 수 있어야 한다. 실패한 요청 때문에 공개되지 않은 파일이 다른 사용자에게 노출되어서는 안 된다.

## 6. 상태와 업무 규칙

### 작품·경매·거래 상태는 분리

| 대상 | 상태 전이 | 규칙 |
| --- | --- | --- |
| 작품 | 초안 → 공개 ↔ 비공개 | 진행 경매의 일반 비공개 전환 금지. 운영 중단은 사유와 취소 처리 필요 |
| 경매 | 진행 → 낙찰 / 유찰 / 운영 취소 | 시작은 서버 시각으로 즉시. 종료 상태에서 재개 불가. 유찰 재출품은 새로운 경매 ID로만 가능 |
| 거래 | 낙찰 시 결제 대기 생성 → 결제 완료 → 전달 중 → 거래 완료 | M2는 테스트 상태만 검증. L 상태 변경 주체·기한·취소·환불 전이는 별도 명세 |
| 협업 | 대기 → 읽음 → 수락 / 거절, 대기·읽음 → 발신 취소 | 수락·거절·취소는 최종 상태. 중복 읽기는 상태를 되돌리지 않음 |

### 경매 규칙

1. 첫 최소 입찰가는 시작가, 이후 최소 입찰가는 현재 최고가 + 1,000원이다. 더 높은 금액으로 입찰할 수 있다.
2. 입찰 처리 시 DB 잠금을 확보한 후 확인한 서버 시각이 `마감 시각 이상`이면 거절한다. 먼저 접속하거나 확인창을 열었어도 입찰 권리를 예약하지 않는다.
3. 서버 내부 저장은 UTC, 화면은 한국 시간과 시간대 표시를 기본으로 한다. 클라이언트 시계·카운트다운을 최종 판정에 사용하지 않는다.
4. 마감 작업 지연 시에도 입찰은 서버에서 차단하며, 화면은 ‘마감 처리 중’으로 표시한다. 마감 작업은 재시도할 수 있고 경매당 결과·거래 기록은 하나만 생성한다.
5. 현재 최고가가 기술 상한이면 추가 입찰을 비활성화한다. 등록자 본인 입찰·사용자 임의 입찰 철회·기간 자동 연장은 M2에서 지원하지 않는다.
6. 네트워크 오류로 성공 여부가 불분명하면 ‘결과 확인 중’으로 표시하고 같은 요청 키로 확인한다. 확정 전 성공·실패를 단정하지 않는다.
7. 낙찰자 연락처는 공개하지 않는다. 거래 당사자에게도 필요한 거래 단계에서만 필요한 정보를 제공한다.

### 순위 규칙

- 작가별 `거래 완료` 상태의 거래 수를 집계한다. 낙찰 건수·입찰 횟수·관심 수·가격 합계를 순위로 사용하지 않는다.
- 운영 취소·환불 처리된 거래는 실적에서 제외한다. 부분 환불 반영 기준은 L 단계 결정 항목이다.
- 테스트/실거래 환경을 분리하고, 테스트 데이터에서는 테스트 순위임을 화면에 명시한다.
- 실적이 0인 작가는 ‘거래 실적 없음’으로 표시하고 번호 순위는 부여하지 않는다. 이는 초안 기준안이며 기존 시안과 다른 점이다.

## 7. 데이터와 서비스 책임

| 데이터 | 주요 내용·제약 |
| --- | --- |
| 계정·작가 | Auth 사용자 ID, 공개 프로필, 인증 상태. 계정당 작가 프로필 하나 |
| 작품·이미지 | 작가 ID, 입력 정보, 공개 상태, Storage 경로, 대표 이미지. 작성자 변경 불가 |
| 경매 | 작품 ID, 시작가·시각·마감, 상태, 시작 당시 작품 조건. 진행 경매 중복 방지 |
| 입찰·거래 | 경매·입찰자·금액·접수 시각·요청 키, 낙찰/거래 상태. 경매당 낙찰 거래 하나 |
| 관심 작품 | 회원·작품 쌍 유일 |
| 협업 요청 | 발신자·수신 작가·유형·연락처·내용·상태·처리 시각 |
| 신고·운영 기록 | 대상, 요청자·처리자, 사유·시각. 일반 회원 수정 불가 |

- **Next.js:** 화면, 입력 보조, 탐색, 결과 표시. 클라이언트 검증은 편의를 위한 것이며 서버 검증을 대체하지 않는다.
- **FastAPI:** 인증 토큰 검증, 권한, 작품·경매·요청 규칙, 결과 반환. 클라이언트가 보낸 소유자 ID·권한·현재가를 신뢰하지 않는다.
- **Supabase:** Auth·PostgreSQL·Storage. 인증 비밀키는 서버에만 두며 보호된 DB·파일의 직접 접근도 제한한다. 서명 업로드를 사용하더라도 본인 경로·용량·유형을 검증한다.
- DB 스키마와 API 경로·요청/응답 명세는 이 기능명세서를 기준으로 다음 설계 단계에서 작성한다. 결제 구현이 없는 M2에 가상의 운영 결제 API를 추가하지 않는다.

## 8. 공통 오류와 화면 품질

| 상황 | 사용자에게 보여줄 동작 |
| --- | --- |
| 잘못된 입력 | 해당 필드와 이유 표시, 입력 내용 유지 |
| 인증 만료 | 재로그인 안내, 원래 페이지로 복귀. 제출은 다시 확인 |
| 접근 권한 없음 | 정보 노출 없이 접근 불가 안내 |
| 작품 삭제·비공개 | 열람 불가 안내와 목록으로 돌아가기 |
| 가격 변경·마감 | 최신 상태를 표시하고 기존 확인 내용으로 제출하지 않음 |
| 목록 조회 실패 | 빈 결과와 구분한 오류·재시도 버튼 |
| 저장·업로드 실패 | 성공으로 표시하지 않고 입력 보존·재시도 제공 |
| 반복 요청 제한 | 잠시 후 재시도 안내. 로그인·입찰·파일·협업 요청에 서버 측 제한 적용, 수치는 운영 설정에서 결정 |

필수 화면은 360px 모바일과 1440px 데스크톱에서 내용·버튼이 잘리지 않아야 한다. 키보드만으로 탐색·폼 제출·확인창 닫기가 가능해야 하며, 닫힌 확인창은 원래 버튼으로 초점을 돌린다. 이미지 대체 설명, 폼 라벨, 색상 이외의 상태 문구를 제공한다.

저장·입찰은 서버 응답 후 완료 표시한다. 현재 데이터의 실시간 갱신 방식은 후속 기술 설계에서 선택하되, 조회 화면이 오래되더라도 입찰 서버 검증은 항상 최신 데이터를 사용한다. 비밀번호·토큰·협업 요청 본문·개인 연락처를 일반 오류 로그에 남기지 않는다.

| AT-16 | INQUIRY-01~02 | B가 A에게 요청 → B 보낸함·A 받은함에 표시. D 직접 조회 거절, 재시도 중복 없음 |
| AT-17 | INQUIRY-03 | A 수락과 B 취소 동시 요청 → 한 상태만 확정. 최종 상태 뒤 변경 거절 |

| AT-19 | DIGITAL-01 | 디지털 작품은 px·파일 형식으로 전시. 정책 미확정 상태에서 실거래 시작은 차단 |

## 10. 후속 결정과 구현 순서

| 결정 | 필요한 시점 | 미결정 시 적용 범위 |
| --- | --- | --- |
| 학생 인증 자료·검토·보관 방식 | L 작품 판매 공개 전 | M1·M2 미인증 테스트 등록만 허용 |
| 디지털 판매 횟수·독점성·이용 범위 | L 디지털 경매 전 | 디지털 전시·테스트 경매까지 |
| 결제 사업자·수수료·정산·미결제 처리 | L 결제 개발 전 | 결제 대기 상태의 테스트 흐름까지만 |
| 실물 상태·액자·배송비·수령·반품 조건 | L 실물 경매 전 | 실제 판매 시작 금지, 입력·표시 명세 보완 필요 |
| 환불·부분 환불의 실적 반영 | L 순위 운영 전 | M2는 전액 취소/환불 테스트 건 제외 |
| 배포 서비스·예산·팀 일정 | 운영 배포 전 | 로컬·분리된 테스트 환경 개발 |

구현 순서: M1 계정·프로필 → 작품·공간 안내·검색 → M2 경매 → 커리어·협업·운영 → 인수 테스트 → L 상세 정책·거래 명세.

다음 산출물은 M1 데이터 모델·API 명세와 구현 작업 목록이다. 미확정 실거래 정책을 임의 확정하지 않고, 각 단계의 완료 기준으로 구현 결과를 검토한다.
