# Design Farm — 일상에 머무는 예술

2026-10-09 새 디자인 버전. **Next.js + TypeScript / FastAPI 기반 로컬 웹앱**입니다. 데이터는 SQLite에 저장합니다. Supabase 연동과 공개 배포는 아직 하지 않았습니다.

기존 `index.html`, `check.cjs`는 비교용으로 보존했습니다. 이전 설명은 [README.legacy.md](README.legacy.md)에 있습니다. **새 버전은 HTML 파일을 더블클릭하는 대신 서버를 실행해야 합니다.**

## 실행

준비: Node.js 20.9 이상, pnpm, Python 3.12. 검증 환경은 Node 24.19 / Next 16.4 / Python 3.12입니다. 프런트엔드 의존성은 `frontend/pnpm-lock.yaml`, Python 의존성은 `backend/requirements.lock.txt`에 고정했습니다.

처음 설치:

```powershell
cd frontend
pnpm install --frozen-lockfile
cd ../backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.lock.txt
cd ..
```

Windows 실행:

```powershell
./start-local.ps1
```

[http://127.0.0.1:3000](http://127.0.0.1:3000)을 여세요. 실행 스크립트는 창을 띄우지 않고 서버를 시작하며 로그를 `output/`에 기록합니다. 이미 사용 중인 3000·8000 포트의 프로세스를 종료하거나 대체하지 않습니다.

직접 실행하려면 두 터미널에서 각각:

```powershell
# 터미널 1: backend 폴더
.venv/Scripts/python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000

# 터미널 2: frontend 폴더
pnpm dev
```

이 PC에서는 Codex의 Node/Python 환경으로 설치를 마쳤습니다. 다른 PC에서는 위 도구부터 설치해야 합니다. 서버는 로컬 주소에만 바인딩합니다.

## 로그인과 마이페이지

- 회원가입, 이메일·비밀번호 로그인, 로그아웃, 7일 세션.
- 로그인 페이지에서 **체험 계정 입력하기**를 누른 뒤 로그인할 수 있습니다.
- 체험 계정: `collector@designfarm.local` / `Gallery2026!`. 공용 테스트 계정이므로 실제 개인정보는 넣지 마세요.
- 마이페이지에 **내 활동 / 관심 작품 / 등록한 작품 / 협업 요청함 / 프로필 설정**을 모았습니다. 상단 주 메뉴의 내 활동은 제거했습니다.
- 비밀번호는 솔트를 사용하는 scrypt 해시로 저장합니다. 세션은 HttpOnly·SameSite=Strict 쿠키이고 DB에는 토큰 해시만 저장합니다.
- 관심 작품·등록·입찰·협업 요청은 `backend/data/gallery.sqlite3`에 남아 새로고침과 서버 재시작 후에도 유지됩니다. 이 폴더는 Git에서 제외했습니다.
- 이메일 인증·비밀번호 재설정·소셜 로그인·학생 인증은 아직 없습니다. 로컬 HTTP용 쿠키 설정은 인터넷 운영용 설정이 아닙니다.

## 새 디자인과 기능

- 여백과 작품 사진 중심의 미술관 디자인, 회화·조소·공예 예시 이미지 8점.
- Design_Farm 아치 심볼 로고, 읽기 쉬운 로그인 소개 영역, 12개 프로필 분야 선택 및 직접 입력.
- 검색, 종류·공간 필터, 정렬, URL 조건 복원, 관심 작품, 상세 보기.
- Three.js 조형 스터디: 드래그 회전, 방향 버튼, 자동 회전 일시정지, 시점 초기화. 움직임 줄이기 설정과 대체 이미지 지원.
- 이미지 업로드, 실물 치수, 재료, 작가 노트, 추천 공간, 배치 방식, 시작가·기간을 입력하는 작품 등록.
- 입찰 금액 확인 단계, 익명 입찰 이력, 서버 마감 판정과 계정별 결과.
- 협업 요청의 보내기·받기·수락·거절·취소. 앱 내부 요청함에 저장하며 이메일은 발송하지 않습니다.

모든 예시 작품·작가는 가상입니다. 사진처럼 보이는 이미지도 AI 생성물입니다. **built-in image_gen**으로 제작한 원본은 `frontend/public/artworks/`, 최종 프롬프트는 [첫 작품 4점](docs/generated-artworks.json)과 [추가 작품 4점](docs/additional-artworks.json)에 있습니다. 화면은 Next.js 이미지 최적화를 사용합니다.

## 기존 문제 수정

| 문제 | 새 구현 |
| --- | --- |
| 본인 입찰을 화면에서만 차단 | 서버가 세션 사용자와 소유 작가 ID를 비교해 거절 |
| 동명이인 작품·실적 혼합 | 고유 ID로 작품·요청·실적 연결 |
| 상한 이후 제출 불가능한 폼 | 1억 원 첫 입찰 허용, 최고가가 상한이면 추가 입찰 종료 |
| 남은 시간 표시 지연 | 서버 시각을 보정한 매초 표시, 주기적 서버 상태 조회 |
| 입찰 이력 화면 누락 | 금액·시각·본인 여부 표시, 타인 연락처·계정 비공개 |
| 낙찰을 완료 실적으로 계산 | 낙찰과 거래 완료 분리, 완료 0건은 번호 순위 없음 |
| 새로고침 시 데이터 소실 | SQLite 저장과 서버 세션 |
| 중복·동시 입찰 | 쓰기 트랜잭션, 요청 키 중복 방지, 최신 최소가 재검증 |

금액은 1,000~100,000,000원, 1,000원 단위입니다. 예상 가격대 1만~10만 원은 강제 상한이 아닙니다. 첫 입찰만 있어도 시작가에 낙찰됩니다. 마감 결과 체험은 소유자 또는 입찰 참여자에게만 허용됩니다.

**실제 결제·정산·배송은 없습니다.** 낙찰은 `awaiting_payment` 테스트 상태이며 완료로 자동 전환하지 않습니다. 테스트 거래 완료 상태를 만드는 운영 UI도 이번 범위에는 없습니다.

## 3D · AR 공간 배치 데모

`/space` 또는 작품 상세의 **3D · AR로 공간에 놓아보기**에서 시작합니다. 8점의 작품을 선택하고 좌우 위치, 회전(입체 작품), 중심 높이(벽 작품), 비교 크기 50~150%, 벽 색상을 바꿀 수 있습니다. 기본 100%는 등록 cm 치수를 미터로 변환한 비율입니다.

- 3D 조소·도자 4점은 사진에서 영감을 받은 형태와 절차적 재질로 제작했습니다. 정확한 스캔은 아닙니다. 나머지는 등록 사진 패널이며 배경도 함께 보입니다.
- 지원 브라우저에서는 WebXR 카메라 AR 버튼이 활성화됩니다. 사용자 동작으로 권한 요청 → 수평면 인식 → 1:1 배치/재배치 → 종료를 구현했습니다. AR에서 벽 작품은 수평면 위에 세운 사진 패널로 표시합니다.
- 현재 실행은 **PC 로컬 전용**입니다. 모바일 카메라 AR은 HTTPS 접속과 WebXR hit-test/DOM overlay 지원이 필요합니다. 이 환경에서는 가상 공간과 비지원 안내를 검증했고, 실제 AR 기기 검증은 남아 있습니다. 로컬 서버를 외부에 공개하지 않았습니다.

구현 범위와 후속 계획은 [AR 메모](docs/ar-extension.md)를 참고하세요.

## 검증

```powershell
# backend
.venv/Scripts/python.exe -m unittest test_app -v

# frontend
pnpm typecheck
pnpm build
node --test tests/spatial-dimensions.test.mjs

# 저장소 루트: 이전 HTML 시안 검사

```

서버 통합 검사 13개: 로그인·세션·로그아웃, 비밀번호 해시, 미로그인·외부 출처 차단, 동명이인, 업로드 검증·접근 제한, 본인 입찰, 금액 제한·상한, 단독 낙찰·유찰·마감, 동시 입찰, 재시도 중복, 계정별 관심 작품, 협업 권한·최종 상태, 프로필 권한, 추가 작품 마이그레이션과 데이터 보존. 검사는 임시 DB만 사용합니다. 별도 공간 치수 검사 1개로 모델 크기와 원점을 확인합니다.

브라우저에서는 로그인·새로고침 유지·관심 작품·입찰 확인과 이력·필터 URL 복원·마이페이지, 360px/1440px 반응형 화면을 점검했습니다.
